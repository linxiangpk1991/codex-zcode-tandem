# Codex × ZCode · Tandem 操作说明

使用真正的 ZCode 引擎和用户的 Coding Plan。保留用户当前选择的 Codex 总控模型与思考强度。默认 GLM-5.3、thought=max；GLM-5.3-Flash 只在明确选择时使用，不替换为其他引擎或付费 API。

源码目录是本文件的上一级目录；安装器生成的技能入口会记录实际源码路径与 Node 路径。runtime/ 与 references/ 均相对源码目录，不相对用户的业务项目目录。不要借用作者或其他用户的路径、账号。

支持 Windows、Node 24.19.0。执行入口是 runtime/run-task.mjs REQUEST.json，控制入口是 runtime/control.mjs PROGRESS.json COMMAND.json。尚未安装或找不到原生引擎时，阅读 [安装与排障](installation.md)，先运行 scripts/setup.mjs --check。

ACP 精确锁定 zcode-acp-server 0.65.1。每次调用使用隔离配置，不修改 ZCode 桌面全局设置。验证结果和限制见 [验收说明](acceptance.md)。

桌面更新后，运行只读 `setup --doctor` 比较桌面/CLI/ACP 版本及原生入口 SHA256；CLI 版本不变不代表源码未变。快速 `setup --check` 使用元数据及上次成功 probe 缓存，普通任务不重复启动版本命令或哈希。成功 probe 只记录连接兼容性，不证明真实推理或任务验收。

## 首审、修复和交付

实现请求会自动追加最终首审。声明 `delivery.candidateFiles`、相关功能路径 `userPaths` 和 `verification` 回执；只有 `delivery.status=ready_for_controller_review` 才进入总控独立验收。退出码 4 表示调用结束但交付未就绪。

提供允许的真实测试命令；环境仅总控可用时，由总控运行并回传实际失败。补齐回执后用 `check-evidence.mjs handoff` 重检，不重做实现。浏览器功能看 DOM、请求和持久化读回，视觉由具备视觉能力的总控验收，不自动切换模型。暂停、首审后纠偏和候选变化都不能沿用旧首审。[交付与恢复](delivery.zh-CN.md)

## 分工与输入

总控确定需求、工作目录和基线、负责与保留路径、禁止效果和验收条件。ZCode 负责连贯阶段内的实现、测试和修复。总控负责决策、整合、真实用户路径验收和最终判断。不要为 ZCode 已负责的阶段再创建重复的 Codex 执行者。

ZCode 不会继承当前聊天，明确传入必要的原始需求和项目规则；使用 [委派模板](worker-prompts.md)。同一会话自审不属于独立审查；独立审查采用新的受限会话或工作流中的独立命名角色。

原生工具权限不是操作系统沙箱。发布、生产、财务和凭据操作仍受已有授权与效果控制约束。

## 执行与观察

请求明确设置绝对 cwd、resultFile、progressFile，以及 model、thought=max、mode=build、allowToolKinds 和 timeoutSeconds。默认时限 5400 秒，最大 7200 秒。客户端内置总时限和任务进程清理；若宿主提供或要求有界执行器，则通过它启动并预留清理时间。本技能不依赖任何个人 Harness，不需要常驻远程控制中心。

action=probe 可在无模型推理的情况下检查连接和实际配置。推理前读取模型、模式、思考强度的生效值。心跳与真实活动分开；updatedAt 更新不代表任务取得进展。结合 controls、pendingInput、currentTurn、lastTool、workflow、error 判断。

[实时控制](live-control.md) 包含查询、追问、纠偏、暂停和回答问题的方法。新提示在安全边界串行执行；暂停不撤销已完成写入。未知结果先读回再继续。

额度不足不允许切换付费渠道。机器级自动恢复监视器关闭；恢复前核实指定任务状态。定时跟进或自动化必须有用户请求。

## 原生工作流

顺序工作用普通阶段包。需要并行角色、依赖汇合、持久节点结果、运行中调整并发或中断恢复时，阅读 [原生工作流](native-workflows.md)。

启动或修订前审查完整脚本并绑定 SHA-256 与规范模型标识；修订还绑定前序 run ID。权限回调受校验，实际工具输入另行核对。恢复的原生会话可能省略权限回调，因此不能宣称这些检查能保证执行前拦截。

只允许脚本声明的角色和责任，不递归扩展委派。独立角色有独立上下文，但提示词中的“只读”不是工具隔离。ACP session ID 与 workflow run ID 不相同。

可在验证范围内调整运行中工作流的并发；改变脚本或目标需要已审查的修订，或暂停、读回、续接。排队中的前台纠偏不会直接改写已启动角色的指令。

## 验收与恢复

核对实际 diff、有效测试、权限事件和原生状态。ACP end_turn 不等于业务验收。普通后台交接需要原生终态和完成通知均结束；检查截断标志，必要时定向获取原生日志。

中断后沿用原 session/cwd，仅提交未完成工作。复用未受影响的通过结果；同因失败两次后诊断，不盲目重放，更不能自动重放结果未知的外部写入。

报告行为变化、修改文件、真实命令与结果、session/run 标识和限制。配置 90 分钟时限不等于已通过 90 分钟无人值守压力测试。

升级前停止活动调用并保留既有结果。安装器更新已有入口时要求 --replace，会生成原入口备份并保留其他文件；回退见安装说明。不要用旧版本接管运行中的新版本任务。

公开版技能名是 codex-zcode-tandem，自用版 zcode-native 的源码与入口独立，不自动迁移或覆盖。

## 1.1：请求迁移与验证

默认 GLM-5.3/max，Flash 只在明确选择时使用。编辑/执行请求须声明 workspace 的负责路径、保留路径及完整已审命令；没有声明会被拒绝。先读 [工作区与验证回执](execution-safety.zh-CN.md)。

总控准备独立基线，不让 ZCode 自行收起共享修改或删除 worktree。权限回调不是操作系统沙箱，原生已允许、恢复或后台调用可能不发回调。用真实执行器回执判断测试，completed 不等于 pass。summaryFile 提供摘要；纠偏记录区分排队和执行时间。升级不能热替换其他调用正在用的文件，旧调用继续使用原入口。
